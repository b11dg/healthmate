# Feature Workflow

Задача навыка — вести процесс реализации фичи (фазы дорожной карты HealthMate) от постановки задачи до Pull Request в `master`. Процесс и git-конвенции подробно описаны в `context/ai-interaction.md` — прочитай его перед выполнением любого действия, если ещё не читал в этой сессии.

## Рабочий файл

`context/current-feature.md` содержит описание текущей фичи. Пути `context/…` отсчитываются от корня репозитория.

### Структура current-feature.md

- H1 — название активной фичи или `# Current Feature`, когда активной фичи нет
- `## Цели` — маркированный список критериев приёмки
- `## Заметки` — дополнительный контекст, решения, детали (в духе раздела «Решения» в архивных мини-спеках `context/feature/phase-*.md`)
- `## История` — список реализованных фаз/фич. Новые записи добавляются, предыдущие не редактируются

Фича активна, если H1 содержит её название вместо `Current Feature`, а `## Цели` содержит критерии приёмки. Если файл отсутствует или не содержит активной фичи — предложи выполнить `load` перед `start`, `review` или `complete` и не выполняй эти действия.

## Действия

Первое слово `$ARGUMENTS` — команда, остальной текст — её аргументы. Передавай в файл действия только аргументы, без имени команды.

| Действие | Описание |
|----------|----------|
| [`load`](actions/load.md) | Загрузить требования (из файла или текстового описания) в `context/current-feature.md` |
| [`start`](actions/start.md) | Создать ветку `feature/<slug>` от `master` и начать реализацию активной фичи |
| [`review`](actions/review.md) | Проверить реализацию фичи против целей и сформировать отчёт |
| [`complete`](actions/complete.md) | Архивировать мини-спеку, обновить `current-feature.md`, закоммитить, запушить ветку и подготовить PR в `master` |

Читай только файл выбранного действия. Примеры вызова:

- `$feature load Фаза 5 — realtime-статусы и геймификация` — сформировать мини-спеку из текстового описания
- `$feature load phase-5-draft` — прочитать `context/feature/phase-5-draft.md`, если такой черновик уже есть
- `$feature start` — начать реализацию активной фичи
- `$feature review` — проверить результат
- `$feature complete` — завершить и подготовить PR

Если команда не задана или неизвестна — объясни доступные действия. Команды `start`, `review` и `complete` аргументов не требуют.

## Git и подтверждения

Ветки, коммиты, push и PR — по правилам `context/ai-interaction.md`. В частности: **push ветки и создание PR через `gh pr create` всегда подтверждаются у пользователя перед выполнением**, даже в рамках `feature complete` — это не разовое разрешение на будущее. Мёрдж PR в `master` тоже не выполняется автоматически без отдельного подтверждения.

Не переспрашивай повторного согласия на обычные шаги, уже разрешённые пользователем в текущей сессии. Уточнение нужно перед перезаписью активной фичи, при неоднозначных изменениях (что коммитить) или если что-то в файле не соответствует ожидаемой структуре.
