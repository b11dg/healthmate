# Load Action

1. Проверь аргументы после команды `load`:
   - Если это имя файла (совпадает с существующим `context/feature/{name}.md`) — прочитай его. Не добавляй расширение `.md` повторно, если оно уже указано.
   - Если это текстовое описание функциональности — используй его, чтобы оформить `context/current-feature.md` по структуре мини-спек (`context/feature/phase-*.md`): «Решения», «Модель данных» (если есть новые сущности), «Экраны», «Что делает агент», «Что делает пользователь», «Критерии приёмки». Не выдумывай архитектурные решения — если что-то неочевидно (например выбор между Supabase Realtime и SSE), сначала обсуди с пользователем, потом фиксируй.
   - Если файл не найден или неясно, что передано — файл или описание, попроси уточнение. Не превращай отсутствующее имя файла в требования автоматически.
   - Если аргументов нет — попроси указать имя файла или описать, что нужно реализовать.

2. Обнови `context/current-feature.md` (или создай, если отсутствует):
   - Перед заменой активной фичи — получи согласие, если пользователь ещё не разрешил её перезаписать.
   - В H1 укажи название фичи (например `# Фаза 5 — Полировка и деплой`).
   - В `## Цели` — маркированным списком проверяемые критерии приёмки.
   - В `## Заметки` — решения, дополнительные детали, открытые вопросы.
   - Сохрани `## История` и все предыдущие записи без изменений.

3. Подтверди, что файл обновлён, и дай краткое резюме целей.
