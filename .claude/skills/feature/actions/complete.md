# Complete Action

1. Прочитай `context/current-feature.md` и проверь наличие активной фичи по правилам `SKILL.md`. Проверь, что все пункты `## Цели` выполнены, и прогони `npm run build`. Если остались невыполненные цели или сборка не проходит — сообщи об этом и не продолжай завершение.
2. Убедись, что текущая ветка — `feature/*`. Целевая ветка — всегда `master`.
3. Проверь незакоммиченные изменения, включая подготовленные к коммиту. Закоммить только изменения текущей фичи с содержательным сообщением в стиле `git log` (например `Phase 5: realtime статусы обработки, геймификация`). Не включай посторонние правки; если один файл содержит изменения разного назначения, закоммить только относящиеся фрагменты. Если принадлежность изменений неоднозначна — уточни у пользователя. Если релевантных изменений нет — пропусти коммит.
4. Архивируй мини-спеку: скопируй содержимое `## Цели` и `## Заметки` из `current-feature.md` (плюс H1 как заголовок) в новый файл `context/feature/phase-N-<slug>.md` — тот же slug, что использовался для ветки в `feature start`, номер фазы — следующий по порядку после существующих файлов в `context/feature/`. Оформи как остальные архивные мини-спеки (см. `context/feature/phase-4-rag-chat.md` для структуры разделов).
5. Обнови `context/current-feature.md`:
   - Верни H1 в `# Current Feature`.
   - Очисти содержимое `## Цели` и `## Заметки`, сохранив заголовки.
   - Добавь в `## История` запись с названием и кратким описанием реализованной фичи (в стиле существующих записей). Сохрани предыдущие записи.
   - Обнови таблицу дорожной карты в `context/project-overview.md`, если статус фазы там ещё не отмечен как «Готово».
   - Закоммить это обновление отдельным коммитом с сообщением `chore: обновление current-feature.md после завершения [название фичи]`.
6. **Спроси подтверждение** перед push — покажи, что будет запушено (ветка, коммиты). После подтверждения выполни `git push -u origin feature/<slug>`.
7. **Спроси подтверждение** перед созданием PR — покажи предполагаемые заголовок и текст (краткое summary целей из архивной мини-спеки, ссылку на `context/feature/phase-N-<slug>.md`). После подтверждения выполни `gh pr create --base master --head feature/<slug> --title "..." --body "..."`.
8. Сообщи ссылку на PR. Мёрдж PR в `master` и удаление ветки фичи — отдельные подтверждаемые действия, не выполняй их автоматически в рамках `complete`. Напомни, что после мёржа ветку стоит удалить (`git branch -d feature/<slug>` локально и `git push origin --delete feature/<slug>` — тоже по подтверждению).

## Ошибки

Если любой шаг завершился ошибкой (конфликт при коммите/пуше, отклонённый push, `npm run build` падает) — останови последовательность и сообщи о текущем состоянии и причине остановки. Не переходи к следующим шагам так, будто предыдущий завершился успешно.
