# Фаза 3 — Анализы

Мини-спека к `context/SPEC.md` (Дорожная карта, Фаза 3). Цель фазы — пользователь загружает PDF с результатами анализа крови, получает структурированные показатели с отметкой отклонения от нормы и видит динамику показателя между несколькими анализами. Это сценарии 3–4 из SPEC.md — основная ценность продукта.

## Решения

- Хранение файлов — Supabase Storage, приватный bucket `lab-reports`, путь файла включает `userId` (доступ только через signed URL на своём сервере)
- Парсинг — Google Gemini API (`@google/genai`, бесплатный тир — выбран вместо Claude API, чтобы не привязывать карту и не тратить деньги на pet-проект), PDF передаётся напрямую как inline-документ (Gemini тоже понимает PDF нативно) — без отдельной библиотеки для экстракции текста из PDF
- Промпт + `responseSchema` заставляют Gemini вернуть строгий JSON-массив показателей (название, значение, единица, нижняя/верхняя граница нормы); ответ дополнительно валидируется перед записью в БД
- Обработка — синхронная, прямо в API-маршруте загрузки (пользователь ждёт ответ несколько секунд). Realtime-статусы и фоновая обработка — Фаза 5, здесь не делаем
- Сопоставление показателей между отчётами для тренда — по точному совпадению названия (без нормализации синонимов вроде "Гемоглобин" / "Hb") — упрощение для pet-проекта
- Флаг отклонения (`low`/`normal`/`high`) вычисляется на сервере сразу после парсинга, не на клиенте

## Модель данных (добавляется к `prisma/schema.prisma`)

- `LabReport`: id, userId, fileName, filePath (путь в Storage), status (`processing`/`done`/`error`), errorMessage?, reportDate? (дата забора анализа, если распознана), createdAt — 1:N от User, 1:N с LabResult
- `LabResult`: id, labReportId, name, value, unit, refLow?, refHigh?, flag (`low`/`normal`/`high`/`unknown`) — принадлежит LabReport

## Экраны

1. `/labs` — список загруженных отчётов (имя файла, дата, статус) + кнопка загрузки PDF
2. `/labs/[id]` — детали отчёта: таблица показателей с значением, единицей, нормой и визуальным флагом отклонения
3. Блок динамики на `/labs` или `/labs/[id]` — выбор показателя → график (Recharts) со значениями этого показателя из всех отчётов пользователя, где он встречается

## Что делает агент (в коде)

1. Установить `@google/genai`
2. Добавить модели `LabReport`, `LabResult` в `prisma/schema.prisma`, `npx prisma db push`
3. Server Action/route handler загрузки: валидация файла (тип `application/pdf`, лимит размера — например 10 МБ), загрузка в Supabase Storage, создание `LabReport` со статусом `processing`
4. Вызов Gemini API с PDF-документом и промптом на строгий JSON; парсинг и валидация ответа; запись `LabResult`; обновление статуса `LabReport` на `done` — либо `error` с сообщением при сбое (нечитаемый файл, невалидный JSON от модели, превышен лимит бесплатного тира и т.п.)
5. Страницы `/labs` и `/labs/[id]` под защищённым layout
6. Компонент графика динамики показателя (переиспользует паттerns из `dashboard-charts.tsx`)
7. Проверка контраста флагов отклонения (не только цвет — иконка/текст, как требует дизайн-система)

## Что делает пользователь (вне кода, руками)

1. Создать приватный bucket `lab-reports` в Supabase Storage
2. Получить `GEMINI_API_KEY` в Google AI Studio (бесплатно, без карты), добавить в `.env.local` и в переменные окружения Vercel
3. Прогнать сценарий: загрузить PDF анализа → увидеть распарсенные показатели с флагами → загрузить второй анализ с тем же показателем → увидеть тренд на графике → попробовать загрузить нечитаемый/не-PDF файл и убедиться, что ошибка обработана понятно

## Критерии приёмки

- [x] Пользователь может загрузить PDF с результатами анализа крови
- [x] Файл проходит валидацию (тип, размер) до отправки в обработку
- [x] Показатели анализа распознаются и сохраняются структурированно (название, значение, единица, норма)
- [x] Отклонение от нормы отмечается визуально флагом (не только цветом)
- [x] Динамика конкретного показателя между несколькими анализами отображается на графике
- [x] Ошибка парсинга (нечитаемый файл, сбой LLM) не роняет приложение — отчёт помечается статусом `error` с понятным сообщением
- [x] Изменения задеплоены на Vercel и доступны по публичной ссылке

Первые шесть пунктов проверены локально сквозным сценарием (два синтетических PDF-анализа + один нечитаемый как анализ файл, оба реальных провайдера — Supabase Storage и Gemini API). Тестовые данные удалены из БД и Storage после проверки.
