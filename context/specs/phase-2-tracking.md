# Фаза 2 — Базовый трекинг

Мини-спека к `context/SPEC.md` (Дорожная карта, Фаза 2). Цель фазы — пользователь заводит профиль, ежедневно логирует питание/воду/вес/сон и видит динамику на дашборде. Авторизация и БД уже готовы (Фаза 1).

## Решения

- UI-компоненты — свои лёгкие примитивы в `src/components/ui` поверх Tailwind (не shadcn/ui: у проекта уже своя палитра токенов в `globals.css`, полноценный shadcn/ui принёс бы свою систему токенов и лишний вес для десятка форм)
- Графики — Recharts
- Тема (светлая/тёмная) — через `next-themes` или ручной класс на `<html>` + `prefers-color-scheme`, переключатель в шапке, выбор сохраняется в `localStorage`
- Приёмы пищи на этом этапе — только вручную (продукт + КБЖУ введены пользователем), поиск по базе продуктов — не в MVP
- Все данные пользователя достаются в Server Actions/route handlers по `session.user.id` — без явного `WHERE user_id`, где возможно, положиться на Prisma-запросы, ограниченные текущим пользователем (RLS на уровне Postgres — по возможности, не блокирует MVP если не успеем)
- Один день = локальная дата пользователя (без таймзон на сервере на этом этапе — упрощение для pet-проекта)

## Модель данных (добавляется к `prisma/schema.prisma`)

- `WeightLog`: id, userId, weightKg, date, createdAt — 1:N от User
- `HabitLog`: id, userId, date, waterMl, sleepHours — 1:N от User, один запись на дату
- `MealLog`: id, userId, name, calories, proteinG, fatG, carbsG, eatenAt — 1:N от User
- `Profile` уже существует (Фаза 1) — доиспользуется, без изменений схемы

## Экраны

1. `/login` — форма входа: email + пароль, вызывает `signIn("credentials", …)` из Auth.js, ссылка на `/register`. Сейчас есть только API-маршрут авторизации (Фаза 1) — самого экрана нет.
2. `/register` — форма регистрации: email + пароль (+ подтверждение), создаёт пользователя через существующий `/api/register`, затем авто-логин и редирект на `/profile`. Аналогично — API есть, экрана нет.
3. `/profile` — форма профиля: цель (похудение/набор/поддержание — select), рост, вес, аллергии, ограничения (текстовые поля). Сохранение через Server Action, обновляет `Profile`.
4. `/dashboard` (главный экран после логина) — карточки для быстрого лога (вода/вес/сон/приём пищи за сегодня) + графики динамики веса, воды и калорий за 7/30 дней (Recharts, переключатель периода)
5. Переключатель темы в шапке (доступен на всех защищённых страницах)

## Что делает агент (в коде)

1. Установить `recharts`, `next-themes`; свои UI-примитивы (`button`, `card`, `input`, `select`, `label`) — без внешнего CLI
2. Расширить `prisma/schema.prisma` тремя моделями выше, `npx prisma db push`
3. Server Actions: `updateProfile`, `logWeight`, `logHabit` (upsert по дате), `logMeal`
4. Route handler или Server Component для агрегации данных дашборда (суммы КБЖУ за день, ряды для графиков за N дней)
5. Страницы `/login` и `/register` (публичные) + `/profile` и `/dashboard` под защищённым layout (редирект на `/login`, если нет сессии)
6. Компонент переключателя темы + провайдер в `layout.tsx`
7. Проверить контраст всех новых экранов по токенам дизайн-системы (light/dark) — см. `SPEC.md`

## Что делает пользователь (вне кода, руками)

1. Проверить на деплое после `git push`, что новые таблицы применились (health-check уже есть)
2. Прогнать сценарий руками: завести профиль → залогировать воду/вес/сон/приём пищи за пару дней → проверить, что графики на дашборде отражают введённые данные
