# Контекст проекта: HealthMate

Персональный веб-сервис, объединяющий трекинг здоровья и AI-разбор медицинских анализов в одном месте.

Проблема: анализы обычно лежат в PDF на почте, а трекеры веса, воды и питания живут в отдельных несвязанных приложениях — ни то, ни другое не даёт целостной картины самочувствия.

Ценность: HealthMate хранит историю анализов и повседневные привычки, а AI-чат отвечает с учётом именно ваших данных (через RAG) и переводит отклонения в анализах на понятный язык с конкретными рекомендациями по питанию.

Сервис не заменяет врача и не ставит диагнозы — это подчёркнуто в интерфейсе (см. «Нефункциональные требования» в [architecture.md](architecture.md)).

Pet-проект для портфолио, но не однопользовательское приложение: модель данных и регистрация (Auth.js) рассчитаны на многих пользователей с изоляцией данных по `user_id` с самого начала. Сейчас реальный пользователь один (автор, на этапе разработки) — это текущее состояние, не архитектурное ограничение. За скобки вынесены именно роли/права (админка, модерация и т.п.) — не многопользовательский режим как таковой.

## Сценарии использования

1. Завести профиль и цель (похудение / набор массы / поддержание), указать аллергии и ограничения
2. Ежедневно записывать приёмы пищи, воду, вес и сон — и видеть динамику на графиках
3. Загрузить PDF с результатами анализа крови и получить структурированные показатели с отметкой отклонения от нормы
4. Посмотреть динамику конкретного показателя между несколькими анализами на одном графике
5. Задать вопрос AI-чату и получить ответ, опирающийся на личный профиль и историю анализов
6. Получить персональные рекомендации по рациону на основе цели и показателей

Сценарии 3–5 — основная ценность продукта и главный фокус демонстрации в портфолио.

## Дорожная карта

| Фаза               | Содержание                                                                         | Статус   |
| ------------------ | ----------------------------------------------------------------------------------- | -------- |
| 0. Скелет           | Next.js + TypeScript + Tailwind, git-репозиторий                                    | Готово   |
| 1. Окружение        | Supabase (БД, auth, storage), деплой пустого каркаса на Vercel                      | Готово   |
| 2. Базовый трекинг  | Профиль, вес/вода/сон/питание, дашборд с графиками                                  | Готово   |
| 3. Анализы          | Загрузка PDF, парсинг через LLM, сравнение с нормами, тренды по показателям         | Готово   |
| 4. RAG-чат          | База знаний в pgvector, чат с опорой на профиль и анализы, рекомендации по рациону   | Готово   |
| 5. Полировка        | Realtime-статусы обработки, геймификация (бейджи), финальный деплой                 | Не начато |
| 6. Вовлечение       | Email-напоминания о пропущенном трекинге (нужен email-провайдер, напр. Resend)       | План      |

Перед каждой фазой пишется мини-спека в `context/feature/phase-N-*.md` (архив завершённых фич) — см. [ai-interaction.md](ai-interaction.md) за описанием процесса. Активная задача, над которой идёт работа прямо сейчас, всегда в [current-feature.md](current-feature.md).

В коде: иконка — `src/app/icon.svg` (фавикон), компонент `src/components/logo.tsx`.

Открытый вопрос на будущее: у иконки была идея hover/idle-анимации («дыхание» столбиков) — понравилась по духу, но реализацию (скорость, линейность, анимация высоты, а не только scale) нужно продумать заново, когда дойдём до реального места использования (например, состояние загрузки в Фазе 5).
