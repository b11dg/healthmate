# Фаза 4 — RAG-чат и рекомендации по питанию

Мини-спека к `context/SPEC.md` (Дорожная карта, Фаза 4). Цель фазы — AI-чат отвечает с опорой на профиль пользователя и историю анализов (через RAG по базе знаний в pgvector), плюс отдельный экран с персональными рекомендациями по рациону. Это сценарии 5–6 из SPEC.md.

## Решения

- Эмбеддинги — Google Gemini `gemini-embedding-001` (с `outputDimensionality: 768`) (тот же провайдер, что и парсинг анализов в Фазе 3 — не нужен второй платный ключ), размерность 768
- Поиск по базе знаний — pgvector, cosine similarity, top-5 `KnowledgeChunk` на вопрос. Профиль и последние показатели анализов пользователя — не через векторный поиск (уже структурированы и малы по объёму), подставляются в промпт напрямую обычным запросом к БД
- База знаний — широкий черновик карточек готовит Gemini (не только по показателям, что уже встречались у пользователя, а по типовым показателям крови и общим принципам питания), каждая карточка вычитывается и правится агентом перед загрузкой; при подготовке используются скиллы `pubmed-database` (сверка с актуальными исследованиями через NCBI E-utilities) и `health-coach`/`rp-diet` (evidence-based нутрициологическая база — Renaissance Diet 2.0)
- Стриминг ответа — Vercel AI SDK (`ai` + `@ai-sdk/google`): `streamText()` на сервере (`app/api/chat/route.ts`), хук `useChat()` на клиенте. RAG-сборка контекста (векторный поиск + профиль + анализы) выполняется вручную до вызова `streamText()`; сохранение ответа в БД — в колбэке `onFinish`
- Рекомендации по питанию (сценарий 6) — реализуются дважды с переиспользованием одной and той же RAG-логики: (1) отдельный экран `/recommendations` со структурированным выводом, (2) чип-подсказка в чате для быстрого инлайн-ответа без перехода со страницы
- Дисклеймер «не диагноз, не замена врача» — обязателен в интерфейсе чата и на экране рекомендаций (NFR из SPEC.md)

## Модель данных (добавляется к `prisma/schema.prisma`)

- `Conversation`: id, userId, title?, createdAt — 1:N от User, 1:N с ChatMessage
- `ChatMessage`: id, conversationId, role (`user`/`assistant`), content, createdAt — принадлежит Conversation
- `KnowledgeChunk`: id, content, embedding (vector 768, pgvector), sourceLabel? — не привязан к User, общая база

## Экраны

1. `/chat` — сайдбар со списком разговоров + активный тред сообщений + поле ввода (стриминг ответа) + дисклеймер. При пустом треде — чипы быстрых подсказок («Объясни последний анализ», «Дай рекомендации по питанию»)
2. `/recommendations` — персональные рекомендации по рациону: цель профиля → что есть → чего избегать → привязка к текущим отклонениям в последних анализах; дисклеймер
3. Чип «Дай рекомендации по питанию» в `/chat` — быстрый инлайн-ответ той же RAG-логикой, без перехода на `/recommendations`

## Что делает агент (в коде)

1. Проверить/включить расширение pgvector в Supabase; добавить модели `Conversation`, `ChatMessage`, `KnowledgeChunk` в `prisma/schema.prisma`, `npx prisma db push`
2. Установить `ai` и `@ai-sdk/google`
3. Подготовить базу знаний: сгенерировать широкий черновик карточек через Gemini, вычитать и поправить факты с опорой на скиллы `pubmed-database` и `health-coach`/`rp-diet`, написать разовый seed-скрипт (эмбеддинг каждой карточки через `gemini-embedding-001` (с `outputDimensionality: 768`) → запись в `KnowledgeChunk`)
4. `app/api/chat/route.ts`: принять историю сообщений, сохранить сообщение пользователя, собрать RAG-контекст (top-5 `KnowledgeChunk` по эмбеддингу вопроса + профиль + последние `LabResult`), вызвать `streamText()`, сохранить ответ ассистента в `onFinish`
5. Экран `/chat`: список разговоров, тред с `useChat()`, быстрые подсказки, дисклеймер
6. Экран `/recommendations`: структурированный вывод на основе той же RAG-сборки контекста (без истории сообщений — разовый запрос)
7. Обработка ошибок по NFR: Gemini/эмбеддинг недоступны, лимит бесплатного тира превышен, пустой результат векторного поиска — понятное сообщение, без падения интерфейса

## Что делает пользователь (вне кода, руками)

1. Включить pgvector extension в Supabase (Database → Extensions)
2. Прогнать seed базы знаний один раз после ревью карточек
3. Прогнать сценарий: начать разговор → задать вопрос → получить ответ с опорой на профиль/анализы → нажать чип «рекомендации по питанию» в чате → открыть `/recommendations` → проверить обработку ошибки (например, временно невалидный API-ключ)

## Критерии приёмки

- [x] Пользователь может начать новый разговор в `/chat` и задать вопрос, ответ стримится по мере генерации
- [x] Ответ учитывает профиль и последние показатели анализов пользователя
- [x] Общие факты (нормы, влияние питания) в ответе опираются на базу знаний (RAG), а не только на общие знания модели
- [x] Дисклеймер «не заменяет врача» виден в `/chat` и в `/recommendations`
- [x] История сообщений сохраняется и доступна при повторном открытии разговора
- [x] Экран `/recommendations` показывает структурированные персональные рекомендации по рациону
- [x] Чип быстрой подсказки в чате даёт рекомендацию по питанию без перехода на отдельный экран
- [x] Ошибка LLM или эмбеддинга не роняет приложение — понятное сообщение рядом с чатом/рекомендациями
- [ ] Изменения задеплоены на Vercel и доступны по публичной ссылке

Первые семь пунктов проверены локально сквозным сценарием (тестовый пользователь с профилем, вопрос в чат, чип-рекомендация, повторное открытие разговора, `npm run build` без ошибок). Тестовые данные удалены из БД после проверки. Деплой на Vercel — следующий шаг.
