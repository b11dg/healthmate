# HealthMate — Спецификация продукта

Копия верхнеуровневой спеки из совместного документа (веб-версия с комментариями и историей правок — источник для планирования; эта копия — то, что читает кодирующий агент).

## Видение

HealthMate — персональный веб-сервис, объединяющий трекинг здоровья и AI-разбор медицинских анализов в одном месте.

Проблема: анализы обычно лежат в PDF на почте, а трекеры веса, воды и питания живут в отдельных несвязанных приложениях — ни то, ни другое не даёт целостной картины самочувствия.

Ценность: HealthMate хранит историю анализов и повседневные привычки, а AI-чат отвечает с учётом именно ваших данных (через RAG) и переводит отклонения в анализах на понятный язык с конкретными рекомендациями по питанию.

Сервис не заменяет врача и не ставит диагнозы — это подчёркнуто в интерфейсе (см. «Нефункциональные требования»).

## Целевая аудитория и сценарии использования

Для MVP целевая аудитория — один пользователь (автор проекта), многопользовательский режим и роли вынесены за скобки.

Ключевые сценарии:

1. Завести профиль и цель (похудение / набор массы / поддержание), указать аллергии и ограничения
2. Ежедневно записывать приёмы пищи, воду, вес и сон — и видеть динамику на графиках
3. Загрузить PDF с результатами анализа крови и получить структурированные показатели с отметкой отклонения от нормы
4. Посмотреть динамику конкретного показателя между несколькими анализами на одном графике
5. Задать вопрос AI-чату и получить ответ, опирающийся на личный профиль и историю анализов
6. Получить персональные рекомендации по рациону на основе цели и показателей

Сценарии 3–5 — основная ценность продукта и главный фокус демонстрации в портфолио.

## Дизайн-система

Направление — «мягкий минимализм»: почти монохромная палитра с одним ярким акцентом, поддерживает светлую и тёмную тему с переключением.

| Токен            | Значение | Назначение                                                                                |
| ---------------- | -------- | ----------------------------------------------------------------------------------------- |
| Primary          | #1F2933  | Основной текст и элементы UI в светлой теме                                               |
| Secondary        | #5B6572  | Приглушённый текст (подписи, второстепенные лейблы) в светлой теме — затемнён для WCAG AA |
| Secondary (dark) | #9AA5B1  | Приглушённый текст в тёмной теме                                                          |
| Accent           | #FF6B57  | Бейджи, иконки, крупные нетекстовые элементы                                              |
| Accent-strong    | #CC3B26  | Заливка кнопок с белым текстом (контраст 5:1)                                             |
| Background light | #FAFAF9  | Фон страницы в светлой теме                                                               |
| Background dark  | #16181C  | Фон страницы в тёмной теме                                                                |

Типографика: Manrope (700–800) для заголовков, Inter (400/500) для основного текста. Минимальный размер текста в интерфейсе — 14px.

Доступность (WCAG 2.1, уровень AA):

- Все пары текст/фон проверены на контраст ≥ 4.5:1 для основного текста
- Accent (#FF6B57) используется только для фонов/иконок, не как цвет текста и не как заливка кнопок с белым текстом — для этого Accent-strong
- Состояния (ошибка/предупреждение) передаются не только цветом, но и иконкой/текстом
- Видимый focus-индикатор на всех интерактивных элементах при клавиатурной навигации
- Тачабельные цели кнопок/чекбоксов — не менее 44×44px

### Брендинг

Логотип утверждён (отдельная сессия по неймингу и визуальной идентичности, 2026-09-26): **иконка Rising Bars** (три растущих столбика, самый высокий — акцентным Accent-strong `#CC3B26`, читается как «показатели растут / контроль над здоровьем») в паре с уже согласованным wordmark **`healthmate.`** (строчными, Manrope 800, точка в цвете Accent-strong).

Отклонённые направления — Vital Trend (кардиограмма, слишком клише), Two Circles/Orbit/Ripple (нужен был пояснительный контекст), Heart Check и Goal Ring (Goal Ring дошёл до финала наравне с Rising Bars, но не выбран), Flagged Row (слишком привязан к одной фиче анализов).

В коде: иконка — `src/app/icon.svg` (фавикон), компонент `src/components/logo.tsx` (иконка + wordmark для шапки и других мест использования).

Открытый вопрос на будущее: у иконки была идея hover/idle-анимации («дыхание» столбиков) — понравилась по духу, но реализацию (скорость, линейность, анимация высоты, а не только scale) нужно продумать заново, когда дойдём до реального места использования (например, состояние загрузки).

## Модель данных

| Сущность       | Назначение                                                                   | Связи                                      |
| -------------- | ---------------------------------------------------------------------------- | ------------------------------------------ |
| User           | Аккаунт, аутентификация                                                      | 1:1 с Profile                              |
| Profile        | Цель, рост/вес, аллергии, ограничения                                        | принадлежит User                           |
| LabReport      | Загруженный файл анализа, дата, статус обработки                             | 1:N от User, 1:N с LabResult               |
| LabResult      | Отдельный показатель: название, значение, единица, норма, дата               | принадлежит LabReport                      |
| MealLog        | Запись о приёме пищи: продукты, КБЖУ, время                                  | 1:N от User                                |
| WeightLog      | Замер веса по датам                                                          | 1:N от User                                |
| HabitLog       | Ежедневные отметки: вода, сон, активность                                    | 1:N от User                                |
| Conversation   | Сессия чата с AI                                                             | 1:N от User, 1:N с ChatMessage             |
| ChatMessage    | Отдельное сообщение в чате                                                   | принадлежит Conversation                   |
| KnowledgeChunk | Фрагмент медицинского/нутрициологического справочника + эмбеддинг (pgvector) | используется RAG-чатом, не привязан к User |

Все таблицы с личными данными (LabReport, LabResult, MealLog, WeightLog, HabitLog, Conversation, ChatMessage) изолированы по user_id через row-level security в Postgres.

## Нефункциональные требования

Доступность: интерфейс соответствует WCAG 2.1 уровню AA; контраст текста и интерактивных элементов проверен и зафиксирован в разделе «Дизайн-система».

Приватность и данные о здоровье:

- Сервис не ставит диагнозы и не заменяет врача — явный дисклеймер выводится при первом использовании и рядом с AI-ответами и разбором анализов
- Загруженные файлы анализов шифруются в хранилище, доступ — только владельцу данных (row-level security)
- Проект ведётся как personal-use портфолио-проект, без цели соответствовать HIPAA/152-ФЗ как коммерческий медицинский сервис
- Возможность полного удаления аккаунта и всех связанных данных

Безопасность: валидация загружаемых файлов (тип/размер), защита API-маршрутов через аутентификацию, секреты в переменных окружения, не в репозитории.

Обработка ошибок: приложение не должно падать в белый экран или показывать сырую ошибку Next.js ни при одном ожидаемом сбое (БД недоступна, внешний API — Gemini/Supabase Storage — не отвечает или вернул невалидные данные, файл невозможно распарсить, лимит бесплатного тира превышен). Правило на все фазы:

- Ожидаемые/предсказуемые ошибки (валидация, конфликт данных, неверные креды, сбой конкретной операции с БД/внешним API) — обрабатываются на месте (try/catch в Server Action или route handler) и показываются пользователю как понятное сообщение рядом с формой, без потери введённых данных
- Непредвиденные ошибки (баг, необработанный кейс) — ловятся React error boundary (`error.tsx` на уровне сегмента, `global-error.tsx` на уровне корня) с вежливым сообщением «что-то пошло не так» и кнопкой «попробовать снова», а не падением всего приложения
- Каждая мини-спека, начиная с Фазы 3, обязана явно перечислять сценарии ошибок в своём разделе и включать соответствующий пункт в критерии приёмки

Производительность: обработка загруженного PDF и вызов LLM вынесены в фоновый процесс с уведомлением прогресса через realtime — пользователь не ждёт ответа синхронно.

## Дорожная карта

| Фаза               | Содержание                                                                         | Статус        |
| ------------------ | ---------------------------------------------------------------------------------- | ------------- |
| 0. Скелет          | Next.js + TypeScript + Tailwind, git-репозиторий                                   | Готово        |
| 1. Окружение       | Supabase (БД, auth, storage), деплой пустого каркаса на Vercel                     | Следующий шаг |
| 2. Базовый трекинг | Профиль, вес/вода/сон/питание, дашборд с графиками                                 | План          |
| 3. Анализы         | Загрузка PDF, парсинг через LLM, сравнение с нормами, тренды по показателям        | План          |
| 4. RAG-чат         | База знаний в pgvector, чат с опорой на профиль и анализы, рекомендации по рациону | План          |
| 5. Полировка       | Realtime-статусы обработки, email-напоминания, геймификация, финальный деплой      | План          |

Перед каждой фазой (начиная с Фазы 1) пишется отдельная мини-спека с конкретными экранами, API и критериями приёмки — этот документ остаётся верхнеуровневым и не меняется при каждой фазе.

## Критерии приёмки MVP (Фаза 1)

Фаза 1 считается завершённой, когда выполнено всё нижеперечисленное:

- [ ] Пользователь может зарегистрироваться и войти через Auth.js
- [ ] Пользователь заполняет профиль: рост, вес, цель, аллергии/ограничения
- [ ] Пользователь может записать приём пищи (вручную или через поиск по базе продуктов) и видеть КБЖУ за день
- [ ] Пользователь может записать воду, вес и сон за день
- [ ] Дашборд показывает динамику веса/воды/калорий за последние 7–30 дней на графиках
- [ ] Светлая и тёмная темы реализованы и переключаются в интерфейсе
- [ ] Интерфейс соответствует дизайн-системе и проходит базовую проверку контраста (WCAG 2.1 AA)
- [ ] Проект задеплоен на Vercel и доступен по публичной ссылке

Что сознательно вынесено за рамки Фазы 1: анализы, RAG-чат, рекомендации и геймификация — они в фазах 3–5.
